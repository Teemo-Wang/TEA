# AI Project Team OS｜最小可验证版本（MVP-0）开发规划书 — 给 Codex 执行

> 版本：MVP-0 v1.1｜日期：2026-10-15｜路线：复用 Paperclip 控制面，定制产品界面与流程。
> 依据：完整规划 V0.3.1、首轮本机验证，以及 Teemo 确认的复用路线。
> 本次只调整实施路线与顺序，整体产品目标不变。原版保存为 `AI-Project-Team-OS-MVP0-v1.0-原版备份.md`。
> 第三方能力以固定版本源码及实测为准；未验证的写“未知”，不得臆造参数或把 Agent 自述当作平台证据。

## 1. 产品目标不变

做一个本机打开的中文网页，让不懂代码的人在“项目讨论组”里 `@Codex` / `@DSH` 派活，或请项目经理拆活、解释推荐理由，用户确认后执行；随时看清谁在做什么，找到成果，看效果后接受或返工。

MVP-0 验证三个痛点：不知道派给谁、成果散落难找、多个 Agent 的真实进度不清楚。Teemo 通过浏览器验收，无需阅读代码或终端日志。

最终产品继续遵守 V0.3.1：多项目身份与上下文隔离；安全执行和用户确认合并；后续角色可视化、受控组队与委派；体验成熟后开源。它们没有因为复用 Paperclip 而被取消。

### MVP-0 完成标准

1. 第 9 节三个场景从中文界面发起并完成，用户无需终端或阅读 Diff。
2. 成员卡、任务卡反映真实执行与审批；未知明确显示，不能凭消息或计时器宣告成功。
3. 任一产出在 3 次点击内找到，能追溯项目、任务、成员和第几次尝试。
4. 项目经理推荐有理由、可改派，未确认的计划不会启动执行。
5. 接受与返工从界面完成，每次尝试的历史和成果保留，旧版不会被后续执行覆盖。
6. 正常重启保留记录；执行中服务中断后的状态与进程能被校准，不误报工作中或成功。

## 2. 实施决策：复用底座，做自己的产品

### 2.1 三层边界

```text
Team OS 中文界面
  项目讨论组 / @派活 / 能力表 / 计划确认 / 预览 / 接受与返工
          ↓
Team OS 薄集成层
  身份与数据映射 / 幂等请求 / Attempt 成果版本 / 汇报证据 / 预览边界
          ↓
Paperclip 控制面及适配器
  Project / Issue / Agent / Run / Event / 审批 / 附件与 Work Product
          ↓
Codex / DSH / 可选 OpenAI 兼容 API 项目经理
```

- **唯一任务与执行事实源：Paperclip。** 不再自建第二套任务数据库、调度器、Run 状态机或取消机制。
- 中文产品层通过已有 API、事件和扩展接口接入。Paperclip 原版页面保留作开发诊断工具，不作为最终用户必须学习的操作界面。
- 非核心缺项在薄层补齐；底座缺陷先定位，必要时做可单独测试的小补丁，记录上游维护成本。
- 不为套用原规划而把 Paperclip 数据库换成 SQLite，也不重写已有 Codex 适配器。
- 使用现有本机副本并固定提交。升级底座单独进行，不在验证途中随意拉取最新版本。

## 3. 范围与安全边界

### MVP-0 必做

- 本地单用户中文 Web 应用；首轮支持并实测 macOS，Windows / Linux 保持可移植设计，验证前不承诺支持。
- 三栏项目空间：项目列表、讨论组、成员与任务；消息关联任务，消息不代表执行事实。
- Codex、DSH 直接派活；可选配置 OpenAI 兼容 API 模型担任项目经理，未配置时仍可直接派活。
- 用户可编辑能力表；计划可编辑、改派、删除，确认后才派发，先后依赖必须生效。
- 项目工作目录、每次尝试的成果版本与归档；图片 / Markdown / HTML 预览、打开文件夹。
- 大白话汇报、接受 / 返工、运行取消与超时、重启校准、真实状态。
- 两类最小扩展：Agent 接入与纯数据任务模板；复用已有适配器，不另造通用运行框架。
- 本地持久化沿用底座 PostgreSQL / Drizzle 和文件存储，不复制核心任务状态。
- 密钥使用已有本地 secret 机制，不进 Git、前端响应、事件、日志或报告。

### 暂不做，但保留后续目标

完整 Worktree / Result Commit / 合并；形象与虚拟办公室；自主组队与相互委派；多用户、公网部署；长期记忆检索；插件市场、远程安装与签名；精确费用；容器沙箱；移动端、多频道、`@全体`；专业 Diff 审查界面。

**MVP-0 只允许新建、平台托管的试验项目目录。** 不让 Agent 直接修改用户已有正式仓库。“接受”仅接受当前成果，不等于 Git 合并、发布或部署。已有正式代码项目须先通过完整规划 P0 安全门。

目录约束和可信插件不是操作系统沙箱。不能据此声称已阻止任意文件访问或跨项目泄露；未验证边界如实展示。

## 4. 技术与数据模型

| 层 | 实施选择 |
|---|---|
| 控制面 | 固定 Paperclip，沿用 Express / TypeScript 及既有执行、审批 |
| 产品前端 | React + Vite；优先独立入口或可拆卸模块，通过 API 集成 |
| 数据库 | PostgreSQL / Drizzle，开发可用 embedded PostgreSQL；不用 SQLite 作第二事实源 |
| 实时 | 消费底座实时接口与持久 Run Event；如需 SSE，做带持久游标的投影桥，不假设已原生支持 SSE 重放 |
| Agent | 底座内置 / 外部适配器；命令、版本、认证、取消、会话以实测为准 |
| 成果 | 附件 / Work Product + 不可变内容快照，以 Run ID 关联 |
| 密钥 | 底座 secret 存储，产品配置只保存非密钥字段及引用 |

### 概念映射

| Team OS | 底座映射 / 补充规则 |
|---|---|
| Project | Paperclip Project；Company 是底座作用域，用户无需学习组织结构 |
| Agent 档案 | 框架、模型、能力经验；项目成员实例、上下文和会话需限定项目 |
| Task | Issue，不另存可独立变化的任务状态 |
| Attempt | 用户执行 / 返工的编号，关联一个或多个 Run；底座恢复或重试不自动等同用户返工 |
| Message / Plan | 底座评论 / 文档 / 扩展存储；计划确认幂等，重复点击不重复建任务 |
| Review | 审批策略 / 决策；执行成功、任务交付、用户接受分别表达 |
| Artifact | 附件 / Work Product，关联项目、Issue、Attempt、Run、Agent、哈希及相对路径；重复登记不重复展示 |
| Event | 底座持久事件与来源序号；产品投影可重建，重复事件不重复生效 |
| 能力表 / 模板 / 偏好 | 薄层扩展数据，不复制执行事实 |

Attempt 的存储与事务边界在 M1 定稿。建议 `projects/<project-id>/tasks/<issue-id>/attempt-<n>/`；执行目录与归档快照分开；返工基于旧版副本，旧快照只读，不再作为运行 cwd。文件名不同不算平台版本隔离。

所有映射保留 companyId / projectId 并校验归属。同一 Company 的不同 Project 不自动等于隐私隔离；需验证成员、会话、文件与 API 可见范围，未通过前不开放真实私有多项目使用。

### 状态规则

- 输出不代表完成，Task done 不代表 Run succeeded；以真实 Run / 进程证据为准。
- 成功退出且成果收集结束后才显示“做完了，等你看效果”；失败、超时、取消分别显示。
- 取消先显示“正在停止”；记录终止证据，无法确认则显示“停止结果待确认”。
- 重启校准运行、队列和进程；证据不足标“未知 / 意外中断”，不能静默宣告成功。
- 接受记录真实 Review；返工创建新 Attempt，保留意见和旧成果。

## 5. Agent 接入与启动规范

适配器记录框架、供应商、实际模型、系统 CLI / 内置依赖版本、认证、cwd、非交互、流式事件、取消、超时、会话恢复、Token / 费用能力。能力值为 `supported / partial / unsupported / unknown`，保留证据摘要。

1. **Codex：** 复用 `codex_local`；ACP 是当前候选，原 CLI 收尾单独记录，不能延长超时掩盖。内置依赖与系统 CLI 分别记录。
2. **DSH：** 先探测程序、help、非交互、输出、认证、取消，再选外部 Adapter 或最小包装，不套用 Codex 参数。
3. **项目经理 API：** 仅讨论、生成计划和解释证据，不执行命令或自行派活。未配置凭据不阻塞直接派活。
4. **启动：** 固定 Node / pnpm 与独立实例；测试用实验开关记录原因，不冒充正式默认配置。
5. **跨平台：** 不写死开发机路径；路径用系统 API，打开文件夹按平台分支。交付实测 macOS 双击启动和中文说明。

探测失败只阻塞依赖该能力的步骤，其余授权工作继续；缺用户配置时说清缺什么，不编造参数。

## 6. 最小插件机制

保留“文件夹 + 清单”的用户扩展体验，复用底座运行能力；不要求重写 Paperclip 内置 Codex 来迎合自有格式。

| 类型 | 产品入口 | 实现 |
|---|---|---|
| `task-template` | `plugin.json` + `template.md`、变量、期望产出、推荐成员 | 纯数据校验与渲染，不执行代码 |
| `agent-adapter` | 成员配置、适配器注册描述 | 引用内置 Adapter，新增 Agent 优先底座外部 Adapter 契约 |

清单包含 id、name、version、apiVersion、type、description、entry 或 adapter 引用、声明权限。桥接字段与兼容版本在 M2 实测后定稿，不声称与 DSH / Paperclip 原生清单兼容。

```json
{
  "id": "template-blender-doc",
  "name": "Blender 工作流说明",
  "version": "0.1.0",
  "apiVersion": 1,
  "type": "task-template",
  "entry": "template.md",
  "permissions": ["project-files:write"],
  "template": {
    "suggestedAgents": ["codex", "dsh"],
    "expectedArtifacts": ["markdown"],
    "variables": [{"key": "brief", "label": "工作流描述", "required": true}]
  }
}
```

插件页有扫描、启停、版本、声明权限及错误；坏清单不影响应用。停用拒绝新派活，已运行任务处理方式明确展示。

声明权限需落实到宿主 API；密钥按引用提供。清单不是隔离，含代码的适配器视为可信代码；首版不开放任意远程安装，提示“只安装你信任的插件”。

## 7. 中文界面与项目经理

### 项目空间

- 左侧：项目列表、新建项目、成果库、能力表、插件、设置。
- 中间：讨论组，包含消息、计划卡、任务卡、汇报和审批；`@` 选择成员。
- 右侧：成员真实状态、当前任务、运行时长、可折叠输出、取消与任务列表。
- 普通留言在未配置项目经理时只保存，提示可 @ 成员，不自动建任务。

### 看效果、接受与返工

- 展示各次尝试、成果、验证清单和来源，原始日志折叠。
- 图片直接显示，Markdown 清洗，HTML 通过只读预览服务和隔离 iframe。
- HTML 允许交互脚本，但不得获得主应用同源权限、鉴权信息或任意目录访问；仅暴露当前成果快照，校验路径与符号链接。M1 验证具体方案。
- 接受提交真实审批和意见；返工附意见创建新尝试。失败有原因与下一步，不让状态下拉静默失败。
- 打开文件夹定位当前尝试；成果可追溯到任务、成员和 Run。

### 能力表、设置、项目经理

- 能力表：速度、质量经验、成本 / 额度、标签、备注、更新时间；示例写明是用户经验而非评测。
- 设置：Agent 检测、版本、模型、认证、超时、根目录、API 参数与配置状态；不向前端回传真实密钥。
- 项目经理输出经校验的任务标题、指令、推荐成员、理由、依赖；解析失败不派活。
- 计划可编辑改派；确认后按依赖派发，记录确认版本、覆盖操作与幂等键。
- 汇报分“平台验证 / Agent 自述 / 推断 / 未知”，引用执行与成果证据；无模型时用平台模板。

## 8. 里程碑与推进规则

按 M0 → M4 推进，每阶段给简短进展与验收入口。已授权的常规开发、修复、验证持续进行，不重复索要确认；用户验收、凭据缺失、合并或发布等节点按需停下说明。

### M0｜固定底座，通过执行稳定性门（当前）

交付：能力矩阵、固定配置、启动说明、问题清单、实测报告。

- [x] 同一配置连续 3 个真实文件任务正常收尾，Run 和成果均有证据。
- [x] 干净取消场景无重复手动唤醒干扰，进程树退出；观察期间不被旧队列重启。
- [ ] 超时与认证 / 程序不可用明确报错，不长期假忙碌。
- [x] 网页完成带意见审批；缺意见时有可理解的处理路径。
- [x] 单份成果不重复登记 / 展示，重复请求行为有证据。当前由交付层内容键保证，不宣称原始上传接口天然幂等。
- [x] 正常重启记录一致；运行中停启已用正常 SIGTERM 验证，不用空闲重启替代。

**M0 当前判断（2026-10-15）：** 执行、干净取消、交付、网页审批和正常停启恢复已达到“可进入 M1 做单 Agent 产品闭环”的条件。认证不可用的专项错误路径，以及断电 / 强杀恢复仍未通过，不能写成完整稳定性验收。M1 必须基于 Run、进程与停止确认字段投影状态；当 Issue 仍为 `in_progress`、但最新 Run 已取消且 `executionCancellation.state` 仍为 `requested` 时，显示“已停止，确认未闭环”，不得显示“仍在工作”或“已成功”。

**进入 M1：** 核心执行、取消、交付、审批稳定可用；其余差异有明确边界。若必须重写核心调度或另建任务事实源，重新评估路线。

### M1｜中文单 Agent 产品闭环

交付：三栏页、`@Codex`、成员与任务卡、Attempt 映射、成果版本、预览、接受 / 返工。

- [x] 中文界面新建托管试验项目和派活，状态来自底座。
- [x] HTML 交互、Markdown / 图片可预览，不能读取其他项目或主应用凭据。
- [x] 接受 / 返工界面完成，旧尝试不覆盖，成果不重复。

## 10. 开发与验证纪律

1. 本文控制当前实施范围，完整目标以 V0.3.1 为依据；记录差异，不静默删减目标。
2. 核对实际 API / Adapter / 插件契约再编码，遵守工作仓库 AGENTS.md。
3. 优先配置、API 与扩展；底座补丁记录触发条件、测试与升级影响。
4. 核心逻辑少量有效测试：幂等派发、重复事件、状态投影、快照不覆盖、路径与权限；界面用真实浏览器验证。
5. API 代操作不算用户界面通过，一次成功不算长期稳定，Agent 自述不算平台实测。
6. 保留用户文件与未提交改动，测试数据分离，不提交密钥或数据库。
7. 交付接入探测、映射与复用边界、启动说明、插件指南、未知项及测试报告。
8. 资料放项目文档目录；在 Paperclip 仓库新增计划则用 `doc/plans/YYYY-MM-DD-*.md`。
